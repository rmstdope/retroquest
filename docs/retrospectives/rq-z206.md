# rq-z206: three e2e specs raced the page they read

## What happened

Three specs failed now and then on main and passed on retry, which `failOnFlakyTests` turns red. In each one the game was right and the spec was wrong: it read the page in two steps, and the page changed between them.

- The Dream spec counted the arrival cards, then waited for a line on a card that had already faded out.
- The checklist spec ran `list.count()` and then `list.first().innerText()`. When the card was removed between the two calls, `innerText()` waited for an element that never came back, and the poll timed out after 15 s. The CI log only showed "Timeout … waiting on the predicate".
- The narration spec read the number of shown paragraphs, then the number of unshown ones. A paragraph that appeared between the two reads ended the wait with only one paragraph seen.

Once the Dream race was gone, a second cause showed: a page read before it is laid out shows none of its lines' ends.

## Why

A Playwright locator call is a separate round trip. Two calls made one after the other are two moments, and on a slow runner the page changes in between, here because a card goes on its own when it has been read. An action such as `innerText()` waits on its target with no timeout of its own, so a target that disappears turns into a timeout that names neither the race nor the element.

## Cost

Six of fifteen CI runs on main were red. One bead (rq-wjy0) was parked because of it. This session spent about an hour reproducing the failures before any fix.

## Prevent by

- In `web/e2e/` specs, read the state you assert on in one `evaluate` or `evaluateAll`, and make the read return `null` when the element is gone. Do not follow a `count()` with an action on the same locator.
- To bring a suspected CI-only race out locally, run `CI=1 E2E_CPU_THROTTLE=10 npx playwright test <spec> --repeat-each 10 --retries 0 --workers 4` (the option is in `web/e2e/fixtures.ts`).
